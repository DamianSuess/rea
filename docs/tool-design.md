# Tool contracts

Start from the analyst's question and an existing named contract. Keep provider
protocols and parsing in adapters and reusable workflows in the application layer.
Inputs must preserve caller choices and validate unknown boundary values. Use
tagged Result failures for expected errors and retain useful partial facts.

Return useful observations inline with source identity, provenance, coverage and
limitations. Keep observations, derivations, inferences and unknowns distinct.
Unexamined records are unknown, not absent. Bind file identity to an owned
snapshot and normalize at the format owner's boundary rather than reparsing raw
values in consumers. Bound allocations and representation expansion before work.

Do not advertise unimplemented operations. The current surface consists of two
CLI commands; MCP, sessions and persistent Evidence workflows are unavailable.
New interfaces must have exact named contracts, matching schemas, examples and
public-workflow verification. If an MCP adapter is added, validate schemas after
SDK conversion against the declared dialect and actual clients. Engine-side
JavaScript and non-C# implementations are excluded by the repository policy.
